## 1. 文档目的

将当前讨论中已确认的 QuickEdit 产品需求、边界、优先级和验收口径沉淀为可执行基线，供设计、开发、测试和后续迭代共同使用。

### 1.1 产品定位

- QuickEdit 是一个 Windows 优先的轻量本地文件工作区，核心价值是“打开快、编辑够用、阅读稳定、文件操作直接”。
- 它不是 IDE、Office 替代品或大型文件管理器；首版只做高频、明确、低负担的能力。
- 默认不依赖云服务；文件正文、配置和批注均保存在本地。
### 1.2 核心设计原则

- 懒加载：打开文件夹时只枚举元数据，用户选中文件后再加载正文。
- 能力分级：文本/Excel 可编辑，PDF/DOCX 只读；复杂格式不做“伪 Office”。
- 原文件优先：批注不写回原文件，而是使用独立伴生文件。
- 可配置：可打开后缀、文本大小上限、批注扩展名、工作区恢复等由配置控制。
- 操作可预期：移除工作区不等于删除；重命名只针对单个文件，并同步处理伴生批注文件。

## 3. 用户界面与交互需求

主界面固定采用“左工作区 + 右内容区”的双栏结构；批注打开时从最右侧扩展第三栏，不改变左侧文件工作区的语义。

- 左侧顶部：品牌 Logo（带 ▾ 角标）；点击 Logo 弹出菜单，仅两项——“打开文档”与“新增工作区”，全局添加入口只保留这一个。设置不再并列于侧栏顶部。
- 左侧主体：VS Code 风格树形列表，节点分三类——固定“文档”分区、工作区（行内显示来源路径）、可嵌套文件夹；文档为叶子节点，展示类型、名称、状态；支持展开/折叠、选中、右键、从列表移除。
- 打开文档的归属：通过“打开文档”加入的文件统一挂在“文档”分区下（只记录引用，不移动磁盘位置）；在“文档”分区新建的文档默认落盘到 文档/quickedit/（系统“文档”目录下的 quickedit 子目录）。
- 树形交互：点击工作区/文件夹行展开或折叠；点击文档行在右侧打开；行悬停显示“＋”（仅工作区/文件夹，弹出“新建文件夹 / 新建文档”）与“×”（从列表移除）。
- 右侧顶部：当前文件名、类型/大小/编码信息，以及重命名、批注、保存等高频动作。
- 右侧主体：根据 FileHandler 展示文本编辑器、表格编辑器或 PDF/DOCX 阅读器。
- 最右侧批注栏：可折叠；展示当前文件对应的伴生批注文件及批注列表。
- 底部状态栏：展示当前模式、行数/Sheet/页码、编码、批注文件名等上下文。
### 3.1 关键交互约定

- 左上角 Logo 是全局唯一“添加”入口：弹出的菜单只包含“打开文档”（归入“文档”分区）与“新增工作区”（将文件夹作为工作区加入树）。
- “文档”分区固定存在、不可移除；其下新建的文档默认保存路径为 文档/quickedit/。
- “×”只从工作区移除，不删除磁盘文件，也不删除 .qnote。
- 折叠仅影响左侧树展示，不关闭已打开的文档；移除当前打开的文档时，右侧回到“未选择文档”空状态。
- F2、顶部“重命名”、文件右键菜单均可触发单文件重命名。
- Ctrl+S 与顶部“保存”执行当前可编辑文件保存；只读文档的保存按钮应禁用或不展示。
- 点击“批注”后展开最右侧批注栏；再次点击或点击关闭按钮收起。
- 打开文件夹后不得一次性读取所有正文；文件被选中时才读取。

## 5. 批注伴生文件规范

批注机制是 QuickEdit 的核心差异化能力之一。首版采用简单、可读、可迁移的 JSON 文本格式，并使用专属扩展名 .qnote。

### 5.1 命名规则

```text
README.md        -> README.md.qnote
report.pdf       -> report.pdf.qnote
budget.xlsx      -> budget.xlsx.qnote
```

采用“完整原文件名 + .qnote”而不是“去扩展名 + .qnote”，目的是避免同目录下 report.pdf 与 report.docx 争用同一个 report.qnote。

### 5.2 最小数据结构

```json
{
  "version": 1,
  "target": "report.pdf",
  "updatedAt": "2026-09-15T16:28:00+08:00",
  "annotations": [
    {
      "id": "note-001",
      "scope": "page",
      "locator": { "page": 2 },
      "text": "第 2 页这里需要复核。",
      "createdAt": "2026-09-15T16:20:00+08:00"
    }
  ]
}
```

- version：用于未来格式升级。
- target：记录关联文件名；重命名时同步更新。
- scope：至少支持 general；处理器可扩展 selection、page、cell 等。
- locator：可选定位信息；不存在时仍可作为全文批注使用。
## 6. 非功能需求

性能、稳定性和可预期性优先于功能数量。以下指标为 V1 设计目标，最终验收应以选定技术栈和基准机实测为准。

| ID | 类别 | 要求 |
| --- | --- | --- |
| NFR-PERF-001 | 启动 | 空工作区冷启动目标 ≤ 1s；不得在启动阶段解析 Excel/PDF/DOCX。 |
| NFR-PERF-002 | 目录 | 打开文件夹仅枚举元数据；树形列表的大目录子级必须支持虚拟化或等价策略，避免大目录 UI 卡顿。 |
| NFR-PERF-003 | 懒加载 | Excel/PDF/DOCX 相关解析组件只在首次需要时加载。 |
| NFR-STAB-001 | 稳定性 | 任何单文件解析失败不得导致整个程序崩溃；错误应局部显示并允许使用系统程序打开。 |
| NFR-DATA-001 | 数据安全 | 保存/批注写入应采用临时文件 + 原子替换等策略，降低中断导致文件损坏的概率。 |
| NFR-PRIV-001 | 隐私 | V1 不上传文件正文或批注；除非未来明确增加在线功能，否则无后台网络依赖。 |
| NFR-UX-001 | 一致性 | 移除、删除、重命名、保存等高风险动作的语义必须明确，不使用模糊按钮文案。 |
| NFR-COMP-001 | 兼容 | Windows 10/11 为 V1 目标平台；其他平台不作为首版验收范围。 |

## 7. V1 验收场景

首版至少通过以下端到端场景，才能认为产品闭环成立。

1. 从空应用打开一个 .md 文件，编辑内容，Ctrl+S 保存，关闭后由其他程序确认内容已写回。
1. 点击左上角 Logo，弹出“打开文档 / 新增工作区”两项菜单；分别可完成文件打开与工作区新增。
1. 通过“新增工作区”打开包含数百个文件的目录，树中快速出现该工作区；未选中文件不得提前读取正文。
1. “打开文档”加入的文件出现在“文档”分区下；在“文档”分区新建文档后，磁盘上生成于 文档/quickedit/ 目录。
1. 点击工作区/文件夹行可展开折叠；在文件夹行点“＋”新建文件夹/文档，新节点出现在该文件夹下。
1. 打开 >1MB 文本文件，应用按配置明确提示并拒绝内置编辑器加载。
1. 打开 .xlsx，修改单元格并保存；重新打开后修改仍存在，未编辑 Sheet 不应明显损坏。
1. 打开 PDF / DOCX，内容可阅读；保存原文按钮不可用，同时可以添加批注。
1. 为 README.md 添加批注后生成 README.md.qnote；再次打开 README.md 能自动恢复批注。
1. 将 README.md 重命名为 Guide.md 时，README.md.qnote 同步变为 Guide.md.qnote，批注仍可读取。
1. 点击左侧 × 后文件只从工作区消失；磁盘文件和 .qnote 均继续存在。
1. 从 Windows 文件管理器右键选择 QuickEdit 打开文件，文件进入当前 QuickEdit 实例。
## 8. 后续可选能力（不进入 V1）

以下能力可以预留接口，但不应阻塞首版。

- 图片、SQLite、更多 Office 格式的专用 Handler。
- 批注搜索、标签、导出和孤儿 .qnote 修复工具。
- 崩溃恢复草稿、自动保存、文件变更监听与冲突合并。
- Markdown 预览、JSON 格式化、CSV 表格模式等轻量增强。
- 跨平台版本与便携模式。
